# r46.4 — V4L2 stateful-decoder wrap fix

**Author lane:** code1 (continuing the r46/r46.1/r46.2/r46.3
text-over-video arc).

**Scope:** fix the EINVAL-on-OUTPUT-QBUF regression r46.3
introduced on bcm2835-codec wraps. r46.3's STREAMOFF/STREAMON
cycle to clear `capture_drained` was bcm2835-rejected — first
play worked, wrap failed with `feed sample 1: VIDIOC_QBUF
OUTPUT: EINVAL: Invalid argument` and the slide locked to
"holding last frame."

**Origin/main HEAD at fix time:** `dd8fa749` (my r46.3).

**Recommendation (preview):** ship the V4L2-spec-compliant
`VIDIOC_DECODER_CMD V4L2_DEC_CMD_START` resume path + 3
subagent-flagged hardening fixes (size assert, gate-on-drained,
Frame::drop re-QBUF). Preserves r46.2's CMA-budget memoization
+ r46.3's first-play scanout fix.

---

## §A — Root cause (the r46.3 EINVAL)

Live observation on FYS prod after r46.3 deploy at 04:06:48:

```
warn: prime warmup feed sample 1 failed: VIDIOC_QBUF OUTPUT
       (continuing without warmup)
[mem] begin_slide=30 cma=254.4MB bo=2 fb=2  ← first play OK
[mem] begin_slide=31 cma=254.4MB bo=2 fb=2  ← wrap attempt
ERROR: paint_slide (text-over-video) failed:
       feed sample 1: VIDIOC_QBUF OUTPUT: EINVAL: Invalid argument
WARNING: active playlist has no playable slides
         — holding last frame
```

The first play works. On wrap, my r46.3 `reset_for_replay()`
runs STREAMOFF + STREAMON. bcm2835-codec then rejects the
subsequent OUTPUT QBUF with EINVAL.

The V4L2 stateful-decoder spec
(<https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/dev-decoder.html>)
documents a different mechanism for post-EOS resume:
**`VIDIOC_DECODER_CMD` with `V4L2_DEC_CMD_START`**. STREAMOFF/
STREAMON is *also* allowed per spec but discouraged + driver-
specific behavior is implementation-defined. bcm2835-codec falls
into the implementation-rejects camp.

## §B — Fix shape

### B.1 — VIDIOC_DECODER_CMD ioctl wiring

**`renderer/src/v4l2.rs`** (+57 LOC):

- New constants: `V4L2_DEC_CMD_START = 0`, `V4L2_DEC_CMD_STOP = 1`.
- New struct: `V4l2DecoderCmd` (4 + 4 + 64 = 72 bytes, mirrors
  `<linux/videodev2.h> struct v4l2_decoder_cmd`).
- New ioctl: `vidioc_decoder_cmd` = `_IOWR('V', 96, V4l2DecoderCmd)`.
- New compile-time size assertion (subagent-requested) at the
  existing `const _: ()` block to catch struct-size drift.

### B.2 — `Decoder::resume_after_eos()` (replaces reset_for_replay)

```rust
pub fn resume_after_eos(&self) -> Result<()> {
    let mut inner = self.inner.lock().unwrap();
    // Gate on capture_drained: skip the ioctl if not drained,
    // since V4L2_DEC_CMD_START on a non-stopped decoder is
    // implementation-defined and bcm2835 returns EBUSY.
    if !inner.capture_drained { return Ok(()); }
    let mut cmd = V4l2DecoderCmd {
        cmd: V4L2_DEC_CMD_START,
        flags: 0,
        payload: [0u32; 16],
    };
    unsafe { vidioc_decoder_cmd(inner.fd(), &mut cmd) }
        .with_context(|| "VIDIOC_DECODER_CMD V4L2_DEC_CMD_START")?;
    inner.capture_drained = false;
    inner.output_eof_sent = false;
    Ok(())
}
```

Does NOT touch:
- streaming state (`capture_streaming` / `output_streaming` stay
  true)
- `capture_in_flight` tracking
- kernel-side buffer ownership (no QBUF / DQBUF / REQBUFS)

The single ioctl flips the kernel's CAPTURE-queue EOS state
from stopped → running. Cost: <1ms.

### B.3 — `Frame::drop` re-QBUF semantics fix

**`renderer/src/v4l2.rs`** Drop impl:

Previously:
```rust
if !inner.capture_streaming || inner.capture_drained {
    return;  // skip re-QBUF
}
```

The Frame holding the FLAG_LAST buffer is exactly the one that
flipped `capture_drained = true` at `next_frame`. When that
Frame drops, the prior guard skipped re-QBUF → the kernel was
missing one CAPTURE buffer post-resume.

Fixed to:
```rust
if !inner.capture_streaming {
    return;  // tearing down; STREAMOFF reclaims
}
// Re-QBUF unconditionally while streaming, regardless of
// drained -- kernel accepts QBUF on a drained queue, and
// resume_after_eos then has all N buffers available.
```

### B.4 — Caller update

**`renderer/src/video_decode.rs`**:
`reprime_video_decoder_for_loop` now calls `resume_after_eos()`
instead of `reset_for_replay()`. SPS+PPS+IDR primer feed
unchanged (still correct; per spec the parsed SPS/PPS are
preserved across V4L2_DEC_CMD_START but feeding them again is
harmless and defends against drivers that drop the cache).

## §C — CMA budget (preserves r46.2 + r46.3 better)

r46.4 issues exactly one V4L2 ioctl on wrap (VIDIOC_DECODER_CMD).
No buffer pool allocation. No STREAMOFF/STREAMON cycle. No
REQBUFS. CMA stable, same as r46.3:

- r46.3 measured: 180-247 MB across 28 Demo slides
- r46.4 expected: identical
- Pre-r46.2 (per-cycle decoder drop): would have leaked ~24 MB
  per wrap; r46.4 preserves the r46.2 fix

## §D — Subagent review

Sacred pre-commit review surfaced 4 WARN + 1 NIT. **No BLOCKERs.**
3 of the 4 WARNs fixed in v2 of this commit before push:

### Fixed in v2

1. **Missing compile-time size assertion** (`V4l2DecoderCmd`).
   Added to the existing `const _: ()` block at v4l2.rs:324.
   Pattern-match with V4l2Buffer / V4l2Format / etc. Catches
   future struct-edits that break ioctl-size encoding.

2. **`resume_after_eos` was unconditional** — V4L2_DEC_CMD_START
   on a non-stopped decoder is implementation-defined; bcm2835
   returns EBUSY. The caller fires on a userspace sample-counter
   wrap, which CAN precede the kernel's FLAG_LAST emission for
   very short clips. Now gated on `inner.capture_drained == true`;
   no-op otherwise. Decoder stays healthy; primer re-feed
   restarts decoding normally.

3. **`Frame::drop` early-returned on `capture_drained`** — but the
   Frame holding the FLAG_LAST buffer is exactly the one that
   flipped the flag. The prior guard leaked the FLAG_LAST buffer
   from the kernel CAPTURE queue, which would have starved
   bcm2835 (typically needs full N buffers for B-frame reference
   window) on resume. Now gates only on `!capture_streaming`.

### Deferred with annotation

4. **`V4l2DecoderCmd` Rust alignment is 4 but C struct is 8**
   (because of `__u64 pts` in the stop union). Harmless for
   V4L2_DEC_CMD_START with zero payload; aarch64 + copy_from_user
   handles unaligned reads. Will matter only if a future r47+
   adds the STOP path with real pts. Documented in the struct's
   doc-comment; a future STOP addition should `#[repr(C, align(8))]`.

### NIT — annotated

- Lock held across ioctl in `resume_after_eos` diverges from
  feed/next_frame's scoped-lock pattern. Added a 4-line comment
  explaining the intentional choice (single ioctl + no concurrent
  callers at wrap site).
