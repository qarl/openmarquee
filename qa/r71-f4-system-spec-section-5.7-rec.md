```
### 5.7 First-boot seed content

A fresh device isn't blank. `openmarquee-seeded.json` is a marker file the device stamps after its first-boot seed runs; while absent (and storage empty), the seed persists:

- A curated pack of gradient / texture backgrounds (parchment, kraft paper, stained glass, midnight, sunset, brick wall, chalkboard, marble, oak wood, etc.) bundled into the Python package at `backend/openmarquee/seed_assets/backgrounds/`. Generated once via Pollinations by `scripts/generate-seed-backgrounds.py` (re-runnable to refresh).
- The **Welcome** playlist (the device's default) holds three intro text slides — `Welcome` → `to` → `openMarquee` — each pairing a bundled background with a distinct font and outgoing transition (Caveat Brush on chalkboard with fade; Sedgwick Ave Display on brick-wall with wipe; Pacifico on midnight with iris). A freshly-flashed sign powered on for the first time plays the trio in a loop while the operator connects their phone. Identity is the stable `DEFAULT_PLAYLIST_ID` UUID — schedule rules + API references are id-keyed, so "Welcome" is purely the display name.
- A second seeded playlist named **Freedom** holds three protest-poster-style slides — `FREE` → `YOUR` → `SIGN` — on bold display fonts (Bowlby One SC / Archivo Black / Alfa Slab One) over punchy backgrounds. Short 1.5s cadence reads like a chant. Activated by the schedule rule below; otherwise sits as an alternate playlist the operator can drag-edit.
- A schedule rule: **Friday 20:00–20:10 plays Freedom**; the catch-all default falls back to Welcome at all other times. Pre-seeded so a fresh device gets a weekly easter-egg moment without any operator setup.
- Optionally a demo video if one is present at the seed-video path (operator-supplied via `scripts/download-demo-video.sh` — pulls a CC-BY Blender Foundation clip).

Backgrounds + demo video land as available content but aren't auto-appended to either playlist; operators drag them onto the track when they want them.
```

## Recommended rewrite of §5.7

### Before (the current 11-line block)

### After (proposed)

```
### 5.7 First-boot seed content

A fresh device isn't blank. `openmarquee-seeded.json` is a marker file the device stamps after its first-boot seed runs; while absent (and storage empty), the seed persists:

- A bundled image pack at `backend/openmarquee/seed_assets/images/`. The seed registers one ImageSlide per file (accepted extensions: `.jpg`, `.jpeg`, `.png`) named after the filename stem. Sorted by filename so seed order is deterministic across boots. At v1.0.1 the pack is the `seed-media-2026-06-02` manifest (sourced from Civitai Flux + fal.ai Luma Ray-2); the contents rotate at maintainer discretion without spec changes.
- A bundled video pack at `backend/openmarquee/seed_assets/videos/`. Each `{name}.mp4` paired with a `{name}.png` thumbnail in the same directory becomes one VideoSlide; missing-pair entries are skipped with a log line. Structural validation rejects malformed MP4s (no `ftyp` box) and unreadable thumbnails. At v1.0.1 the pack is the same `seed-media-2026-06-02` manifest (looping clips intended as `background_video_slide_id` targets per §5.10).
- Optionally a single legacy demo video at `seed_assets/demo.mp4` (or whatever `OPENMARQUEE_DEMO_VIDEO_PATH` points to). Retained for out-of-band operator drops via `scripts/download-demo-video.sh`. Skipped when the path is absent.
- A **Demo** playlist (the device's default, keyed on the stable `DEFAULT_PLAYLIST_ID` UUID — schedule rules + API references are id-keyed, so "Demo" is purely the display name). It holds the FREE-YOUR-SIGN demo reel: a 19-slide TextSlide sequence escalating from a boot log through synonyms, chant, scream, silence, stadium, panic, and cooldown, stitched with a representative subset of the device's transition palette. The reel slides are the only thing appended to the playlist automatically.

Images, videos, and the legacy demo slot land as available content but aren't auto-appended to the playlist; operators drag them onto the track when they want them.
```

### Why these specific edits

The dispatch's §6 maps directly to the bullets above; recapping
for the admin-Jimmy reviewer:

1. **`backgrounds/` → `images/`.** The pre-r6c4d3ca dir was
   called `backgrounds` because the assets WERE generated as
   backgrounds. They're now general-use images (also work as
   foregrounds, slide content, etc.). Code matches; spec needs
   to catch up.

2. **JPG acceptance.** The pre-rename pack was PNG-only; the new
   pack is all-JPG. Code at `seed.py:285` accepts
   `.jpg/.jpeg/.png`. Spec should describe the accepted set.

3. **No asset-name enumeration.** The current spec enumerated
   "parchment, kraft paper, stained glass, midnight, sunset,
   brick wall, chalkboard, marble, oak wood." That rots the
   moment we rotate. The new text describes the mechanism
   (one ImageSlide per file, sorted, deterministic) and cites
   the v1.0.1 manifest by NAME (`seed-media-2026-06-02`) so a
   future spec reader can correlate the build to the manifest
   doc without the spec text itself needing edits per rotation.

4. **Welcome/Freedom playlist + Friday schedule rule retired.**
   Confirmed by `seed.py:236-240` comment + the live code path:
   only the Demo playlist is seeded; no schedule rule is
   created. The replacement (the FREE-YOUR-SIGN demo reel) is
   described directly. This closes the r47 §F.4 Cluster A doc
   drift.

5. **Video pack added.** New since the prior spec; the new text
   describes the pair-format (`{name}.mp4` + `{name}.png`),
   structural validation, and the §5.10 connection (these are
   intended as `background_video_slide_id` targets).

6. **Legacy single-file demo slot retained, but reframed.** The
   pre-rewrite spec said "optionally a demo video if one is
   present at the seed-video path". That's still true post-r6c4d3ca
   for the `OPENMARQUEE_DEMO_VIDEO_PATH` (or default
   `seed_assets/demo.mp4`) — separate from the new `videos/`
   directory mechanism. The new text calls it out as a distinct
   legacy slot so operators know both surfaces exist.

7. **Demo playlist NAME.** Spec said "the **Welcome** playlist
   (the device's default)". Now it's the **Demo** playlist —
   per the `storage.save_all` id+name coercion at
   `seed.py:231-233` region.

## §G — Open questions for admin-Jimmy

### G.1 Quote the `seed-media-2026-06-02` manifest name?

The proposed text cites it. Admin-Jimmy may prefer to omit the
manifest name from the spec text entirely and leave it as a
delivery-side artifact (similar to how the spec doesn't name
specific PyPI dep versions). The dispatch says
"don't enumerate individual asset names" — that's the binding
constraint. Naming the manifest is one level of abstraction
above the asset list and seems defensible; admin-Jimmy's call.

### G.2 Should §5.10 cross-reference §5.7's video pack?

§5.10 (text-over-video) describes the `background_video_slide_id`
field that maps to a VideoSlide. The pre-rewrite §5.7 didn't
mention videos at all; the new §5.7 does. A cross-reference
from §5.10 → §5.7 ("the operator can pick from the bundled
video pack or any uploaded VideoSlide") would close the loop.
Out of scope for this rec; flag as a §5.10 follow-up if
admin-Jimmy wants it.

### G.3 Pre-rename PNG references in the bundled pack?

The text says "all-JPG" but the code accepts `.png` too — if
the maintainer ever drops a PNG into `images/`, the seed code
handles it. The proposed text says "accepted extensions:
`.jpg`, `.jpeg`, `.png`" which covers this without
overcommitting on the actual pack format.
